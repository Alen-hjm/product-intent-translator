# Product Intent Translator

产品经理与 coding agent 之间的产品意图翻译器。

目标：以尽可能低的表达和决策门槛，把产品想法、界面反馈和后续修改整理为可核对、可交接的需求说明，支持产品持续演进。

## 当前能做什么

加载 [SKILL.md](SKILL.md) 后，让 AI 在对话中：

- 提取产品目标、功能要求、必须保留的约束和可观察的验收条件。
- 区分用户明确要求、已知上下文、AI 建议和未决问题。
- 简单修改直接整理；缺失信息影响实现方向时，只追问关键问题。
- 依据已提供的对话或意图记录更新完整 Prompt，保留没有撤销的决定。
- 将界面反馈和参考转成具体设计要求，交给编程 AI 检查项目并实施。

例如，已确定“浅色主题、无需登录、数据仅存本地”后，追加“增加分类筛选”，应生成同时包含旧约束与新需求的完整 Markdown Prompt。

这是 AI 使用的工作规则。产品实现、界面预览、运行测试和长期状态存储，需要接收方工具执行；skill 本身不会自动完成这些工作。

## 实测状态（2026-09-24）

**对话式需求整理可试用；自动导出仍有缺陷，三项目链路尚未打通。**

| 范围 | 实测结果 |
|---|---|
| Skill 对话行为 | 3 个模拟场景符合核心预期；不是安装后的端到端测试或稳定性基准 |
| 离线导出脚本 | 13 项检查，6 通过、7 失败；可生成文件，但不能可靠保留完整意图状态 |
| prompts.chat 接入 | 当前导出不符合所测 REST / MCP 输入定义 |
| prompt-optimizer 接入 | 当前导出被所测原始导入器拒绝，也不是正确的 MCP 参数 |
| 在线检索、优化、评估和结果回收 | 尚未实现自动调用，也未完成线上验证 |

已知问题包括：官方示例与 Schema 不一致、缺少 intent.json 导出、草稿/版本/锁定状态丢失、已拒绝需求被当作普通需求输出，以及旧 prompt_markdown 遮盖新约束。当前导出不可作为可靠交接依据。

完整结果和验证边界见 [测试报告](TEST_REPORT.md)。本次同步更新说明与测试结论，以上脚本缺陷仍待修复。

## 现在如何试用

1. 在支持 skill 的编程 AI 中加载本仓库根目录的 SKILL.md，或将其作为当前任务的工作规则。
2. 提供你的想法、当前项目背景和必须保留的限制；连续修改时提供已有决定或上一版完整 Prompt。
3. 核对生成的 Markdown Prompt，再交给编程 AI 实施，并以它实际执行的测试和预览为准。

最小输入示例：

> 现有记账页面，把导出按钮文字改成“导出 CSV”，布局和数据处理不变。请整理成可交给编程 AI 的需求说明。

预期：无需追问可从仓库查到的细节；只要求修改文案，并明确保留布局和数据处理行为。

实验性离线导出命令：

```sh
python scripts/pipeline.py examples/short-video-intent.json --out dist
```

该命令只生成 prompt.md 和两个自定义 JSON，不调用外部服务。文件生成成功不代表需求保真或下游可导入。

## 三个项目的分工与集成计划

| 项目 | 分工 | 本仓库接入状态 |
|---|---|---|
| product-intent-translator | 理解并保留产品意图，形成编程 AI 交接说明 | Markdown 工作规则可试用 |
| [prompts.chat](https://github.com/f/prompts.chat) | 保存、检索和复用 Prompt / Skill 资产 | 需要实现具体接口适配与调用 |
| [prompt-optimizer](https://github.com/linshenkx/prompt-optimizer) | 优化提示词、测试模型输出并比较结果 | 需要实现导入或 MCP 适配、调用与结果回收 |

接入差异和待完成步骤见 [集成状态与接口说明](integrations/pipeline.md)。

## 核心方向

### UI 意图对齐

让用户通过自然语言、参考、方案选择、局部比较与 DIY 表达视觉和体验需求。将这些表达转换为可追溯的设计依据与 agent 可执行的要求，并在实际实现后核对结果。原型选择与编辑界面仍属于设计方向。

### 持续演进能力

针对有依据的后续变化，保留合理的产品与代码结构。新增功能时延续已认可的视觉语言，保持旧功能与数据的有效性，同时避免提前堆积无用功能和复杂架构。当前 skill 依赖显式提供的上下文，不具备独立的长期记忆。
